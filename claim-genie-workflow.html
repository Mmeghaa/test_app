Workflow design

Claim Genie integrated with Claim Lens

This workflow translates the reimbursement hospitalization claims-intimation journey into a process map for both the customer mobile app and customer portal. It covers customer actions, UI decisions, claims-system searches, Claim Lens AI document checks, bank/contact validation, and final claim-reference generation.

Case-specific reimbursement workflow

Each case begins after Reimbursement > File a new Claim > applicable benefit selection.

During hospitalization only

Case 1
1
  1. Ask Date of Admission.
  2. Search claims system for same benefit and same DOA.
  3. If main claim exists, guide customer to create before/after claim using existing claim number.
  4. Ask requested claim amount.
  5. Show mandatory hospitalization documents: discharge summary and bills.
  6. Run Claim Lens only if documents are uploaded.
  7. Generate digital QC form and claim reference after consent.

During + before hospitalization

Case 2
2
  1. Ask Date of Admission.
  2. Search claims system for an existing main claim with same benefit and DOA.
  3. Allow combined main and pre-hospitalization expense intimation.
  4. Show mandatory documents for hospitalization and pre-hospitalization.
  5. Handle missing documents with Upload now, Upload later, or Already Uploaded.
  6. Run extraction and surgical-report check when documents are present.
  7. Proceed to digital form QC and reference generation.

During + before + after hospitalization

Case 3
3
  1. Ask Date of Admission for the complete treatment episode.
  2. Search same benefit and same DOA for an existing main claim.
  3. Capture requested amount across during, before, and after expenses.
  4. Show combined mandatory document checklist for all selected benefits.
  5. Apply the same document, AI, surgical-report, and manual fallback rules.
  6. Auto-fill digital form and freeze matching extracted fields.
  7. Submit with consent and generate claim reference.

Before + after hospitalization

Case 4
4
  1. Ask Date of Admission.
  2. Search claims system for existing main claim within +/- 5 days of DOA.
  3. Customer chooses the existing claim number to attach pre/post expenses.
  4. Ask requested claim amount.
  5. Show mandatory bills and benefit-specific supporting documents.
  6. Run Claim Lens only when documents are uploaded.
  7. Finalize digital QC, consent, and claim reference.

Decision rules and system behavior

These rules define how the front-end, claims system, Claim Lens, and bank validation behave at major decision points.

Decision point Condition System / UI action Customer-facing message
Claim type Cashless selected Route to existing cashless flow. Existing cashless workflow will continue.
Reimbursement intent Track your existing Claim selected Show claim number, status, benefit, DOA, and next action. Track status and pending documents.
Applicable benefits File a new Claim selected Show only policy-available benefits. Allow multi-select. You are viewing only the applicable benefits available in this policy.
Existing claim search During hospitalization is part of selection Search same benefit and same date of admission. Main claim already exists; file before/after claim using claim number.
Existing claim search Before + after selected without during Search main claim within +/- 5 days of admission date. Select the existing claim number for before/after hospitalization filing.
Document path Proceed without document Create pre-intimation case. Do not trigger Claim Lens AI. Documents can be uploaded later before processing starts.
Mandatory documents Required document not detected Offer Upload now, Upload later, or Already Uploaded. Some mandatory documents are missing. Upload now, upload later, or confirm already uploaded.
Surgical report Discharge summary indicates surgical case Request surgical report with the same three document choices. A surgical report is required to process this claim.
AI extraction Claim Lens extraction confidence is insufficient Open digital claim form for manual completion. Please complete the claim form manually.
Bank validation New bank details entered Run penny-drop API silently in the background. No penny-drop option is shown to customer.
Bank validation Account holder name does not match policy proposer Ask customer to re-enter bank details or upload cancelled cheque. Entered bank details are not correct. Please re-enter or upload cancelled cheque.

Channel-specific workflow presentation

The mobile and portal surfaces share the same business rules but present them differently for customer convenience.

Mobile app workflow

  • Use a guided stepper with one primary action per screen.
  • Show member card immediately after login for quick confirmation.
  • Use large pictorial cards for hospitalization, before hospitalization, and after hospitalization.
  • Keep document upload mobile-first with camera/gallery/file picker support.
  • Show Claim Lens waiting screen with short reassurance content while extraction runs.
  • Use bottom sticky actions for Proceed without document, Upload & Proceed, and Final submit.

Customer portal workflow

  • Use a dashboard layout with side navigation and a broader content area.
  • Show the member strip in the portal header and keep context visible.
  • Use side-by-side cards for claim type, intent, benefits, and digital QC fields.
  • Provide a larger upload drop zone for multiple documents.
  • Display claim-system match guidance and document checklist together.
  • Show digital form QC, bank validation result, contact details, and consent in one review page.
